# 验证流程

1. `doctor` 检查选中设备和工具链；`smoke` 检查公共构建/运行设施。它们不表示学生实现正确。
2. `reference ID --case 0` 检查快速库，`solution ID --case 0` 检查完整答案。
3. `check ID --case 0` 定位学生的小例问题；随后 `check ID` 覆盖全部声明案例。
4. 对适用案例执行 memcheck、racecheck、synccheck；不能把工具缺失记为通过。
5. 先正确再比较速度，并完成课程要求的源码/设计证据。

检查包含输出预填 NaN 后完整写入、输入不被修改、重复调用、非默认 stream、同量化输入的独立 FP64 oracle。浮点比较与诊断见 numerics；随机种子和每个 case 的用途在课程元数据中明确。未实现入口非零失败；不使用 skip/xfail 或放宽容差制造通关。

报告绑定源代码与依赖指纹，改变实现后旧结果失效。个人数据保存在忽略目录；公共模板只包含测试方法。若出现失败，先固定 case/seed 与首个坐标，再缩小到仍失败的合法域，不立即重写整个 kernel。
